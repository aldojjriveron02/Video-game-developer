The jam a11y findings. Scott and Ghinea's Global Game Jam study: organizers injected an accessibility challenge into a jam with thirty-five jammers; thirty-one answered the questionnaire with strong interest — evidence that a light, explicit a11y challenge inside a jam is "a productive way to promote accessibility awareness." The jam problem in one line: forty-eight to seventy-two-hour builds ship whatever is cheapest, so accessibility only lands if it is scaffolded and FROZEN, not invented, in the final hours. The scaffold model ships: Global Game Jam has run accessibility diversifiers repeatedly — GGJ18 had "One tap for all," "I can see clearly now" with text-to-background contrast at four-point-five to one, "Basics covered" addressing the top-four most-complained-about issues, "Over to you" for configurable speed and size, "Let me see" for customisable colours; GGJ 2025 had "Easy-read"; GGJ 2026 has "Hands Off." The four most-complained-about issues, per Ian Hamilton's observations: fixed control schemes, text size, color reliance, subtitle presentation.

Validation — the freeze checklist with numbers. Game Accessibility Guidelines, Basic tier: thirty checklist items. Flicker and photosensitivity: avoid anything flashing MORE THAN three times per second covering at least twenty-five percent of the screen; avoid flashing sequences longer than five seconds without a skip; never use the term "epilepsy safe" — no test proves it. Text: Amazon's ten-foot UI guidelines recommend a minimum twenty-eight-pixel font; best-practice examples cited are Guacamelee and Lovers in a Dangerous Spacetime. Contrast: aim for WCAG two AA compliant in the Snook checker — four-point-five to one for normal text. W3C's Easy Checks, a ten-point freeze pass for browser games: page title, image alt text, headings, four-point-five-to-one contrast, text resize, keyboard access plus visible focus, form labels, no content flashing over three per second, no autoplaying audio, captions in sync with speaker identification, basic structure. Touch targets: Apple requires forty-four by forty-four points minimum; Android forty-eight; WCAG two-point-five-point-eight sets twenty-four pixels.

The techniques — freeze-safe polish at the DOM layer, no frozen-code changes. GoYomi — Frank Force's vanilla-JS open-source game, the closest shipped model to ours: fully keyboard-playable with Tab plus single-key shortcuts, a "Speak announcements" toggle narrating game state through an aria-live live region, semantic buttons for the whole UI; "built to be played without a mouse or without seeing the board." itch.io's accessibility submission taxonomy across one hundred twenty-five games: Color-blind friendly, Subtitles, Configurable controls, High-contrast, Interactive tutorial, One button, Blind friendly, Textless — the platform expects these as the declared freeze-time feature set. GAG techniques for our slice: subtitles including non-dialogue sounds plus speaker ID — our pilot barks already have visual floaters; separate volume controls and master mute — BGM ducking exists; game-speed and sensitivity adjustments; remapping; no simultaneous presses — our four ON-by-default pilot assist toggles match this pattern, and options ON by default is the guideline-preferred posture.

What to avoid. Never claim "epilepsy safe" — say precisely what was tested. Last-minute changes to FROZEN systems — our juice guard, input buffer, particle pool, and tutorial code path are frozen; any pre-submission a11y change touching them risks regressions; the freeze must be DOM and settings-layer only. Bolt-on untested colorblind modes — an option that doesn't work is worse than none. Subtitles covering dialogue but not gameplay-critical barks and telegraphs. Audio autostart before a gesture. Blocking OS-level accessibility like pinch-zoom or text-resize. Conflating difficulty with accessibility — the four complaint categories are about controls, text, color, and subtitles, not difficulty. Changing the build post-freeze without re-running the ten-point pass.

Shipped examples. GoYomi — the reference implementation for our DOM layer. Guacamelee and Lovers — scalable text. Journey — visual alternatives to audio information. Evil Glitch — a js13k jam winner shipped commercially on Steam, demonstrating the jam-to-frozen-to-shipped pipeline.
