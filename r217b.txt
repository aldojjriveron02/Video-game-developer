The probe execution order: one, boot storage probe — write, read, delete a canary key inside try-catch; two, embed detection — window dot self versus window dot top means itch-iframe mode; three, round-trip — serialize, export string, re-import, compare checksum; four, denied or degraded path — show the aaryte-style warning and surface Export as the primary path. The techniques — last-mile polish. floaty dot dev: single data-only state object — store IDs not object refs; validate function type-checks every field, clamps numbers, defaults missing fields; version field enables migration; throttled saves via dirty flag plus one-second interval; cookies as four-kilobyte fallback versus five-megabyte localStorage; Base64 export string — btoa is encoding, not encryption, treat saves as public; autosave indicator; multiple slots; sequential migration; compression for large saves. Slodds — fourteen shipped games, ten-times retention difference: save at meaningful events — end of round, major purchase, thirty-second timer — plus beforeunload; "version number from day one"; chained migrations so version-one players don't lose progress at version three; typical save under ten kilobytes. Supagames: save only what must persist — not animations; load defensively — "Never assume a save created last week perfectly matches today's code"; Continue appears only if a save exists; Reset asks confirmation; corrupt-save QA — write broken JSON and assert clean failure; the game must stay playable when storage is unavailable. What to avoid. One: no version field — "the most common cause of 'I lost my save' complaints in browser games," fatal for the jam because the bugfix window is effectively a version-two release. Two: treating itch-embed localStorage as durable on iOS — Safari wipes the embedded frame's storage on quit; this is our exact target platform. Never make localStorage the only save path. Three: storage denial with no UX — the aaryte trap; ship the warning plus fallback, not silence.
