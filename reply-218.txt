The jam mobile findings. LD60 confirmed: theme reveal Friday October sixteenth at six PM Eastern, seventy-two-hour window. itch.io is the canonical LD web host. Official itch HTML5 docs: on mobile, itch ALWAYS forces "Click to launch in fullscreen" regardless of desktop embed settings; there is a dedicated "Mobile Friendly" project flag, and if it is NOT enabled, mobile visitors see a warning that the game may not work. Critical packaging detail from itch founder leafo: "the aspect ratio of your embed is used to set the orientation of the device" — the embed's width-by-height ratio steers portrait versus landscape on phones, and mobile games always launch fullscreen. Packaging hard constraints: ZIP only; index.html at the ZIP root; max one thousand files; filenames under two-forty characters; extracted under five hundred megabytes; single file under two hundred; the game is hosted on a subdirectory of itch's HTML CDN — ABSOLUTE paths break, use relative paths; filenames are case-sensitive; external resources must be HTTPS.

Validation — the four-item gate. Gate one: submission-pipeline dry run. Thompson's LD guide: the hour where things go most wrong is submission hour — aim to finish two hours before the deadline; prepare icon, screenshots, gameplay video in that buffer; warm up by submitting a throwaway build beforehand so the pipeline is practiced, not learned at two AM. Gate two: itch project config check — Mobile Friendly ON, embed aspect ratio matching the designed orientation per leafo's rule, viewport dimensions set, test both "launch from game page" AND the direct html dot itch dot zone URL paths. Gate three: real-device validation on iPhone seventeen with Safari — audio unlock on first real tap, forced-fullscreen launch from the itch game page not just the direct URL, rotation, background and foreground bfcache resync, incoming-call interruption, silent-switch state. Gate four: post-jam reality — rate and comment on other games immediately after the deadline, about ten a day after; this drives plays. And LD judging is overwhelmingly desktop; mobile playability is upside, not the primary judged surface.

The techniques — last-mile polish. Audio unlock on iOS and Android: AudioContext starts suspended by autoplay policy; resume it synchronously inside a genuine user-gesture handler — in the same synchronous task, not after an async gap; a volume-zero muted start is an autoplay-allowed condition. Double-tap zoom: CSS-only fix with touch-action manipulation on the game container. iOS long-press callout and selection: webkit-touch-callout none plus user-select none on canvas and UI. Viewport geometry: our existing visualViewport approach matches current best practice for iOS Safari's dynamic toolbar; complement with viewport-fit equals cover plus safe-area insets for the notch and Dynamic Island. Our one-twenty-hertz-safe loop and input buffering map directly to mobile feel; cap devicePixelRatio on canvas to bound fill-rate on phones.

What to avoid. Trap one — confirmed July twenty-twenty-six: itch's forced mobile fullscreen can mis-size the iframe on Android — a nineteen-twenty by ten-eighty Ren'Py web build lost about a third of the bottom of the screen when launched from the itch game page, but rendered correctly via the direct URL; three of four tested phones affected; persisted despite one-hundred-dvh, overflow hidden, viewport-fit cover; tied to open issue itchio slash itch dot io number eight-eight-one. Workarounds: hand out the direct URL or ship native. Trap two: the mobile game-page path is NOT the direct-URL path — always test the actual itch game page on a real phone, never only desktop Chrome emulation. Trap three: absolute asset paths and case-mismatched filenames — invisible on dev machines, fatal on itch's CDN. Trap four: ZIP-only plus file limits. Trap five: spending jam hours on mobile when LD scoring is desktop-first — the known-unfixed fullscreen bug class means mobile can burn the final two-hour buffer.

Shipped examples. Hextris — shipped mobile-friendly browser puzzle game, canvas, keyboard plus touch controls, open source; a concrete reference for the exact input-parity pattern we need. itch's mobile-friendly tag: five hundred fifty-seven games currently tagged; the discovery channel exists and is populated.

The mobile decision: NOT-READY — KEPT as the default LD60 posture. What I implemented this turn: the iOS long-press suppression — webkit-touch-callout none added to the body stylesheet. Our touch-action none already prevents double-tap zoom more aggressively than the recommended manipulation value; user-select none was already in place; DPR is already capped at two with the governor scaling down further. One line of CSS. The spec holds the verdict: promote to CONDITIONAL-mobile-ready only after the four-item gate passes on real hardware. The reasoning is structural: LD judging is desktop-first, itch's forced fullscreen has a known unfixed sizing-bug class, and jam hours are better spent on the M3 VEX duel slice. Ship the LD page with Mobile Friendly ON — cheap upside plus the five-hundred-fifty-seven-game discovery tag — but do not advertise mobile as supported until the gate is green. If the gate fails on hardware during the jam: freeze mobile work behind the JAM_BUILD flag immediately and spend the protected two-hour buffer on icon, screenshots, and video rather than debugging fullscreen.
