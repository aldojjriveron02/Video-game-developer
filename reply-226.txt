The jam save findings. A jam save is the entire persistence story of a seventy-two-hour slice, and it runs in a hostile host. itch.io's official HTML5 docs state games run "by embedding an iframe pointing to your uploaded code," hosted in "a subdirectory on our HTML CDN" — a separate origin from itch.io, requiring relative paths. The implication: our localStorage lives on itch's CDN origin, not our game's page, and the frame is cross-origin-framed — exactly the storage context most vulnerable to browser eviction and tracking-prevention partitioning. LD's own community wisdom treats the deadline as the design constraint: the Ludum Dare Survival Guide devotes its last four-to-eight-hour block to "publish and submit," sets a milestone like "after the halfway mark I will not add any new features," warns "you definitely don't want to be looking for an exporter during Submission Hour," and when the deadline looms says: "Cut. Cut. Cut." And the freeze window is unforgiving: after the seventy-two hours close, judges rate the uploaded build for weeks; a save-breaking schema change or corrupted save discovered mid-rating cannot be hotfixed without violating jam rules. The conclusion: Export-primary — a user-held JSON file — is the only save we fully control across origin moves, browser eviction, tracking-prevention purges, and private-mode sessions. localStorage is a convenience cache, not the source of truth.

Validation — the final save checklist with specifics. The round-trip test: create fresh state, play, save, reload page, load, deep-compare. Defensive load: getItem then null check; JSON dot parse inside try-catch since corrupted data throws; validate the parsed object before applying; apply defensively — health equals saveData dot health or one hundred. Version plus migration: include a saveVersion field starting at one; each release upgrades saves one version at a time via chained migration functions; test migrations with real save files from previous versions. Boot-time storage probe: MDN's documented feature-detection pattern; treat failure as "session only"; and never assume a successful setItem means the data is actually there — verify with getItem for load-bearing values, because Safari's private mode hands you a zero-quota store where setItem silently succeeds but getItem returns null. Failure-mode tests: QuotaExceededError to graceful failure plus a user-facing message; corrupted import to clean rejection, never crash; unknown schema version to refuse or migrate, never silently load; type-check every field, clamp numbers, fall back to defaults. Lifecycle save test: tab close mid-write must leave the previous save intact; use pagehide and visibilitychange plus beforeunload — mobile Safari beforeunload is unreliable. Device-matrix test: run the whole checklist in the actual itch iframe embed AND on iOS Safari.

The techniques — freeze-safe save polish. Single serializable state object plus saveVersion, plain JSON only; derive transient state instead of storing it. Throttled autosave: mark state dirty when it changes, poll every thousand milliseconds and write only if dirty; shipped datum — Cookie Clicker autosaves every sixty seconds plus a manual Save button. Export and import: JSON to Base64 string the player copies or downloads; Cookie Clicker's shipped ExportSave uses a prompt with a textarea, and its loader always Base64-decodes. Checksum: store a CRC32 over the serialized data alongside it; on load, detect corruption before parsing; on mismatch, clear message plus offer previous backup or fresh start — "silent failure is the outcome to avoid above all else." Backup rotation: keep one previous generation; rotate only after the new save's checksum verifies — the browser analog is writing the backup key first, then overwriting the live key. Save indicator UI: show "Saving," "Saved," "Save failed" so the player knows persistence state. Graceful degradation wrapper: 2048's shipped LocalStorageManager probes with a try-catch test-write and falls back to an in-memory fake storage so the game never hard-crashes when storage is denied; never call localStorage dot clear since it wipes unrelated keys.

What to avoid — the save freeze traps. Post-freeze schema drift. localStorage-only in the itch iframe — browsers may clear it without warning; private mode is a zero-quota trap. Cross-origin iframe SecurityError in Safari. Quota traps — about five megabytes per origin on iOS. Naive direct overwrite — a mid-write kill from tab close or iPhone memory-pressure strands you; rotate the backup. Skipping import validation. Silent save failure. Testing only desktop Chrome. And the debug-only export path — the export and import flow must work in the butler-deployed JAM_BUILD on itch, not just dev builds.
