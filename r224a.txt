Full report is in your Drive. The jam audio findings. Audio is the first casualty in jams. Per SunoBoard's game-jam audio guide: "In a forty-eight or seventy-two-hour jam, audio is the first thing to fall off the plan, and silent entries get rated lower" — a one-hour audio plan is the counter-move. Then the two platform traps. Chrome's autoplay policy suspends every AudioContext until a user gesture; LD entries hosted on itch.io run inside an iframe, and iframes can only gain autoplay rights if the parent page extends them via allow equals autoplay. Chrome auto-resumes an AudioContext when the user has interacted AND start is called on a source node — so most games recover on first click, but a judge who never clicks inside the iframe hears nothing. The iOS trap: WebKit bug twenty-three-seventy-three-twenty-two documented that on iOS the WebAudio API is muted when the hardware silent switch is engaged. The fix, available since iOS seventeen: navigator dot audioSession dot type equals playback routes WebAudio through the playback channel, bypassing the mute switch. And the LD rules context: the classic Compo rule is all content created within forty-eight hours; the seventy-two-hour Jam allows pre-existing work — so our existing prototype and synth stack enter legally.
