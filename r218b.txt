Part 2 of 3. Gate four: post-jam reality — rate and comment on other games immediately after the deadline, about ten a day after; this drives plays. And LD judging is overwhelmingly desktop; mobile playability is upside, not the primary judged surface. The techniques — last-mile polish. Audio unlock on iOS and Android: AudioContext starts suspended by autoplay policy; resume it synchronously inside a genuine user-gesture handler — in the same synchronous task, not after an async gap; a volume-zero muted start is an autoplay-allowed condition. Double-tap zoom: CSS-only fix with touch-action manipulation on the game container. iOS long-press callout and selection: webkit-touch-callout none plus user-select none on canvas and UI. Viewport geometry: our existing visualViewport approach matches current best practice for iOS Safari's dynamic toolbar; complement with viewport-fit equals cover plus safe-area insets for the notch and Dynamic Island. Our one-twenty-hertz-safe loop and input buffering map directly to mobile feel; cap devicePixelRatio on canvas to bound fill-rate on phones. What to avoid. Trap one — confirmed July twenty-twenty-six: itch's forced mobile fullscreen can mis-size the iframe on Android — a nineteen-twenty by ten-eighty Ren'Py web build lost about a third of the bottom of the screen when launched from the itch game page, but rendered correctly via the direct URL; three of four tested phones affected; persisted despite one-hundred-dvh, overflow hidden, viewport-fit cover; tied to open issue itchio slash itch dot io number eight-eight-one. Workarounds: hand out the direct URL or ship native. Trap two: the mobile game-page path is NOT the direct-URL path — always test the actual itch game page on a real phone, never only desktop Chrome emulation. Trap three: absolute asset paths and case-mismatched filenames — invisible on dev machines, fatal on itch's CDN.
