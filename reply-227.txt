The jam mobile findings. The ideal LD game "can be played right in the browser, in a few minutes, alone." Judging is by fellow participants, one to five stars across nine categories plus "Coolness" — and a game that needs a phone in-hand, a specific orientation, or a download gets skipped; friction costs ratings. The freeze mechanics: both events add a one-hour Submission Hour after the forty-eight or seventy-two hours to package and submit; porting may legally happen after the hours, but "the longer you wait, the less time participants will have to play your game" — late mobile work directly trades ratings. After submission only certain bug fixes are allowed, no new features, and you post a short change log. The process wisdom: aim for a personal deadline two hours before the real deadline; do a warm-up submission earlier in the jam; ship an MVP first and never be caught without a submittable build; submit early and often; make it browser-playable since most players won't download; capsule art and screenshots take time, budget for them. For our project the synthesis is explicit: mobile is NOT-ready and LD is desktop-first. The mobile freeze is therefore a containment problem, not a feature problem — lock what's done, prevent regressions, reserve jam hours for the theme.

Validation — the final mobile checklist. From abratabia's mobile browser guide: boot and full play in the mobile browser, playable start to finish; controls never cover the action area; audio works — unlock after first tap, mute works, no autoplay before gesture; text readable at phone scale, UI inside safe areas; no horizontal or vertical scroll, page body fixed; frame time under sixteen milliseconds; test on a real device — iOS Web Inspector via desktop Safari's Develop menu; viewport meta present. From supagamesai's mobile-first lesson: start, play, pause, and restart without a keyboard; all tap targets sixty-four pixels minimum; pointer-to-game coordinate conversion correct after resize; readable in portrait and landscape, or explicitly request one orientation. From abratabia's iOS Safari gotchas: touchcancel must be handled — it fires when a system gesture steals the touch; double-tap zoom and the three-hundred-millisecond tap delay must be neutralized; WebGL context-loss must be handled; localStorage subject to tracking-prevention seven-day eviction.

The techniques — freeze-safe mobile polish, only low-risk additive. Viewport meta with width device-width, initial-scale one, maximum-scale one, user-scalable no. Canvas sizing: create in JS, size from innerWidth and innerHeight, multiply by devicePixelRatio capped at two — above two hurts perf with zero visual gain; CSS at one-hundred percent; listen to resize plus orientationchange. Touch input: pointer events, not mouse events; preventDefault to stop scroll and zoom; track each touch by pointerId in a Map for multi-touch. Conflict discipline: touch-action none on game controls ONLY — not globally — so comments, search, and inputs on the itch page still work. Browser chrome: pad UI with env safe-area insets; use dvh units instead of one-hundred-vh. Audio: no autoplay before gesture; create the context early; resume on first tap; re-check suspended state and resume on every input. Perf: requestAnimationFrame only, never setInterval for the loop; batch Canvas2D draws; watch memory — a twenty-forty-eight squared RGBA texture is sixteen megabytes; flag any frame over sixteen milliseconds. Coordinate correctness: convert client and touch coordinates to canvas space after every resize.

What to avoid — the mobile freeze traps. Adding mobile FEATURES during the freeze window — post-deadline edits are bug-fixes-only, so a half-finished mobile feature is a liability. Relying on the Fullscreen API on iOS Safari — not available in browser, PWA only. Relying on screen orientation lock — not supported in Safari outside standalone PWAs; use a rotate-prompt div. The one-hundred-vh bug — mobile browser chrome makes it wrong; use dvh or innerHeight. Global touch-action none or global preventDefault — breaks page inputs and comments on the itch page. Unresumed AudioContext — silent game equals broken game. iOS memory strictness and WebGL canvas resize leaks. Ignoring touchcancel — touches stolen by system gestures leave controls stuck "on." localStorage fragility. Testing only on desktop and shipping the mobile-friendly tag anyway — the tag is a player-facing promise. Spending the Submission Hour on code instead of packaging, screenshots, description, and tags.
