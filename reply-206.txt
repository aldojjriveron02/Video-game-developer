Validation — the real-device protocol from Abratabia and Lacombe. One: test on the LOWEST-END device you intend to support, not just the flagship — "A game that runs at a smooth sixty fps for the first three to five minutes can start to throttle on real hardware." Two: remote debugging — Android via chrome inspect, iOS via Safari Web Inspector — that's how the perf HUD numbers get verified against reality. Three: touch input — respond on touchstart not touchend, no double-tap requirement, swipe accuracy, prevent pull-to-refresh, verify on BOTH iOS and Android, test interruptions — calls, notifications, tab switches. Four: thermal — fifteen-plus minute sessions watching for mid-session throttle; graph frame times; check JS heap. Five: viewport and safe areas — address bar shown AND hidden, rotation, notch and Dynamic Island insets; screen orientation lock works on Android Chrome after fullscreen but NOT on iOS Safari. Six: audio — first-tap Play button, Web Audio resume inside the gesture handler, locked-screen and mute behavior. Seven: storage — iOS ITP evicts site data after seven days without revisiting; versioned saves plus Export-primary is the mitigation. Lacombe's gates: device list, scenarios, edge cases, OS matrix, thirty-fps floor, battery drain, usability pass.

The techniques — last-mile mobile polish. Render at seventy to eighty percent resolution and upscale — the largest single perf lever; target a lower baseline than sixty fps to survive thermal. Prewarm pools, zero-GC loops — our particle pool maps directly. Batch draw calls, medium precision shaders, minimize render-target switches, rAF. iOS Safari specifics: AudioContext suspended until a user gesture — resume inside the tap handler, per context; Safari limits simultaneous audio sources more aggressively than Chrome — cap concurrent voices; NO Fullscreen API in iOS browser — PWA manifest is the only real fullscreen; handle touchcancel since Safari steals edge gestures; touch-action manipulation kills double-tap zoom and the three-hundred-millisecond delay; viewport-fit cover for safe-area extension. Stelabouras' itch traps: every new push generates a new URL — plan a stable entry for the LD link; localStorage inside the itch iframe doesn't persist like a PWA — test saves inside the actual embed; Page Visibility API to pause on tap-out; orientation lock is behind disabled flags on iOS — don't depend on it. Audio architecture: Web Audio for all SFX, never HTML5 elements; one audio element max for streamed BGM.

What to avoid. No Mobile Friendly flag — iOS visitors get an explicit warning. Absolute paths or case mismatches — works locally, four-oh-fours on itch. Assuming fullscreen or orientation lock on iOS — neither exists. Audio without a prior gesture — the rater hears silence. Flagship-only testing. LocalStorage-only saves in the iframe. URL instability across rebuilds. Ignoring touchcancel.
