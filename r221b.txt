W3C's Easy Checks, a ten-point freeze pass for browser games: page title, image alt text, headings, four-point-five-to-one contrast, text resize, keyboard access plus visible focus, form labels, no content flashing over three per second, no autoplaying audio, captions in sync with speaker identification, basic structure. Touch targets: Apple requires forty-four by forty-four points minimum; Android forty-eight; WCAG two-point-five-point-eight sets twenty-four pixels. The techniques — freeze-safe polish at the DOM layer, no frozen-code changes. GoYomi — Frank Force's vanilla-JS open-source game, the closest shipped model to ours: fully keyboard-playable with Tab plus single-key shortcuts, a "Speak announcements" toggle narrating game state through an aria-live live region, semantic buttons for the whole UI; "built to be played without a mouse or without seeing the board." itch.io's accessibility submission taxonomy across one hundred twenty-five games: Color-blind friendly, Subtitles, Configurable controls, High-contrast, Interactive tutorial, One button, Blind friendly, Textless — the platform expects these as the declared freeze-time feature set. GAG techniques for our slice: subtitles including non-dialogue sounds plus speaker ID — our pilot barks already have visual floaters; separate volume controls and master mute — BGM ducking exists; game-speed and sensitivity adjustments; remapping; no simultaneous presses — our four ON-by-default pilot assist toggles match this pattern, and options ON by default is the guideline-preferred posture. What to avoid. Never claim "epilepsy safe" — say precisely what was tested. Last-minute changes to FROZEN systems — our juice guard, input buffer, particle pool, and tutorial code path are frozen; any pre-submission a11y change touching them risks regressions; the freeze must be DOM and settings-layer only. Bolt-on untested colorblind modes — an option that doesn't work is worse than none.
